# TV 漫剧类型支持设计

## 目标

让 TV 端现有的首页追番、追剧、收藏页面，以及个人中心的追番和收藏预览，能正确呈现并打开漫剧。收藏列表中的漫剧还应能正常取消收藏。

## 约束与非目标

- 追番接口的 `type=1/2` 表示番剧/影视列表分类；漫剧是条目自身的 `season_type=12`，不新增追踪列表类别或首页入口。
- 漫剧收藏条目为 `type=24`，剧集 ID 在条目的 `id`，所属 season ID 在 `ogv.season_id`。
- 本次只调整 TV 端界面行为；为支持条目而修改共享 API 数据模型时，不改变 Mobile 端页面行为。
- 不改播放内核或漫剧播放能力。

## 方案比较

1. **沿用现有列表（选定）**：让追番/追剧按现有 API 分类展示其返回的漫剧条目；识别收藏 `type=24`，使用现有番剧详情页打开，并将取消收藏请求带上实际条目类型。无新增入口，符合 API 分类方式。
2. **增加单独漫剧筛选**：在追番/追剧页面新增本地筛选，需要请求现有列表后再按 `season_type` 过滤，并处理两个列表之间的归属或重复；接口没有独立漫剧类别，额外 UI 和请求逻辑不必要。

## 实现范围

- 扩展收藏条目的共享反序列化/映射，保留 `type=24` 与 `ogv.season_id`。
- 将漫剧收藏映射为可跳转 season 的卡片：使用收藏条目 `id` 作为剧集 ID，使用 `ogv.season_id` 作为 season ID。主收藏列表和个人中心预览都走现有 SeasonInfo 页面。
- 收藏页长按漫剧时不使用普通 UGC 的点赞、投币等操作；保留适用的取消收藏与批量删除操作，并让删除 API 使用条目的实际类型。
- 个人中心收藏预览中的漫剧长按不打开普通 UGC 操作菜单。
- 追番和追剧继续走既有分类与卡片交互；确认 `season_type=12` 条目可由响应模型解析并显示，无需新增追踪类型枚举。
- 增加覆盖漫剧收藏数据映射与类型参数的测试，并运行相关模块编译/单测。
