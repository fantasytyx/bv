### 二、弹幕类型与布局

#### 2.1 滚动弹幕 (mode=1)
- 从右向左匀速滚动
- **速度 = 基础速度 × 播放速率 × speedLevel 系数**
  - 基础速度由弹幕飞越屏幕的标准时长决定（约 6 秒）
  - 播放速率：跟随视频变速（1.0x / 1.5x / 2.0x 等），弹幕同步加减速
  - speedLevel（1~10 档）：用户手动叠加的速度偏好，独立于播放速率
- **轨道间距**：同轨道新弹幕必须等前一条完全进入屏幕并留出 `marginPx`（约 0.6 × 文字盒高度）后才可 spawn。所有轨道满时进入 pending 队列延迟重试
- **追赶允许**：spawn 后快速弹幕追上前方慢速弹幕产生视觉重叠是正常行为，不做碰撞检测
- 长文本弹幕限速：`pxPerMs` 上限为短文本速度的 1.5 倍

#### 2.2 顶部弹幕 (mode=5) / 底部弹幕 (mode=4)
- **水平居中**显示，固定 4 秒
- 逐轨道堆叠，同轨道前一条到期后才允许后续弹幕进入

#### 2.3 字体大小与轨道

- **轨道高度**由基准行高决定：`textSizeSp × (textSizeScale / 100)`
- 每条弹幕有 API `textSize`，实际渲染字号 = `min(danmaku.textSize, 25) × (textSizeScale / 100)`（25 为标准字号上限，超过的裁剪到标准）
- 小字号弹幕在轨道内**垂直居中**对齐
- `textSizeScale` 为百分比整数，范围 **25 ~ 200**（表示 25%~200%）

### 四、数据操作

- `appendDanmakus(list, maxItems, alreadySorted)` — 追加数据并限制总条数
- `trimToTimeRange(min, max)` — 裁剪时间范围外数据

### 五、播放同步

通过 Provider 函数每帧查询：
- `positionProvider: () -> Long`
- `isPlayingProvider: () -> Boolean`
- `playbackSpeedProvider: () -> Float`

**DanmakuTimer** 时间平滑：
- `System.nanoTime()` 驱动单调时钟，消除 position 抖动
- Seek / 暂停恢复 / 变速切换时重新锚定
- 极端漂移（>2s）自动修正

暂停时冻结弹幕位置，恢复时继续。

### 六、配置

```kotlin
data class DanmakuConfig(
    val enabled: Boolean,
    val opacity: Float,                // 0.1~1.0
    val textSizeSp: Float,             // 基准字体大小 (SP)
    val textSizeScale: Int,            // 百分比 25~200 (25%~200%)
    val fontWeight: DanmakuFontWeight, // Normal / Bold
    val strokeWidthPx: Int,            // 描边宽度
    val speedLevel: Int,               // 用户滚动速度偏好 1~10
    val area: Float,                   // 显示区域占比 0.0~1.0
    val laneDensity: DanmakuLaneDensity, // Sparse / Standard / Dense
    // 过滤
    val allowScroll: Boolean = true,
    val allowTop: Boolean = true,
    val allowBottom: Boolean = true,
    val minLevel: Int = 0,
)
```

滚动速度最终公式：`pxPerMs = basePxPerMs × playbackSpeed × speedMultiplier(speedLevel)`

---

### 七、过滤

引擎内部维护双份数据：`allItems`（全量原始数据）+ `items`（过滤后数据）。

- `setDanmakus` / `appendDanmakus` 同时写入 `allItems`，并按当前过滤条件生成 `items`
- 帧循环只操作 `items`，不做任何过滤判断
- Config 过滤字段（`allowScroll/Top/Bottom` / `minLevel`）变更时：从 `allItems` 重建 `items` + `seekTo(currentPosition)`
- 过滤条件稳定后，帧循环零过滤开销

---

### 八、Emoji 支持

- **Unicode emoji**（😀🎉 等）：`Canvas.drawText()` 原生支持
- **B站自定义表情**（`[doge]` 等 `[token]` 语法）：解析 → 查询表情 URL → 异步加载图片 → inline segment 绘制。未就绪时画占位方块，就绪后重新构建缓存

---

### 九、渲染管线

```
┌──────────────────────────────────────────────────┐
│  CacheThread (HandlerThread, 低优先级)            │
│  Bitmap 构建请求 → 绘制文字+emoji 到 Bitmap       │
│  → 设置 item.cacheBitmap (volatile)              │
│  → post 主线程 invalidate                        │
└──────────────┬───────────────────────────────────┘
               │
┌──────────────▼───────────────────────────────────┐
│  ActionThread (HandlerThread)                     │
│  Choreographer callback → Semaphore 等 draw 完成  │
│  → act():                                         │
│    1) pruneExpired                                │
│    2) dropIfLagging                               │
│    3) retryPending                                │
│    4) spawnNew（轨道间距检查）                      │
│    5) requestCacheBuilds → CacheThread            │
│    6) 写 RenderSnapshot (双缓冲 A/B)              │
│  → View.invalidateOnAnimation                     │
└──────────────┬───────────────────────────────────┘
               │ latestSnapshot (volatile)
┌──────────────▼───────────────────────────────────┐
│  Main Thread — View.onDraw(canvas)                │
│    1) 读 Provider (position/config/playing)       │
│    2) DanmakuTimer.step() 平滑时间                │
│    3) stepTime + drainReleasedBitmaps             │
│    4) 获取 snapshot → release Semaphore            │
│    5) canvas.clipPath(maskPath)（如有蒙版）        │
│    6) 遍历 snapshot:                              │
│       有 cacheBitmap → drawBitmap                 │
│       无缓存 → drawText fallback                  │
│    7) postInvalidateOnAnimation（局部刷新）        │
└──────────────────────────────────────────────────┘
```

---

### 十、蒙版

在 DanmakuView 的 onDraw 中处理：
- `setMaskFrame(frame)` 更新蒙版帧（volatile）
- onDraw 中 `canvas.save() → clipPath(maskPath) → 绘制弹幕 → restore()`
- SVG Path 解析结果缓存为 Android `Path` 对象，同一 maskFrame 不重复解析

---

### 十一、缓存系统 (CacheManager)

- **BitmapPool**：最大 50MB / 72 个 Bitmap，尺寸近似复用（宽差 ≤48px，高差 ≤24px）
- **生成号**：Config 变更（字号/描边/字体）递增 `cacheStyleGeneration`，旧缓存惰性失效
- **流控**：每帧最多 8 个缓存请求，队列深度上限 48

## 新 BLBL 弹幕系统（参考实现）

位置：d:\code\blbl\app\src\main\java\blbl\cat3399\feature\player\danmaku\

### 架构特点
- **无 ECS**：直接命令式设计，更轻量
- **三线程**：Main（绘制）/ ActionThread（每帧逻辑）/ CacheThread（异步缓存构建）
- **双缓冲快照**：RenderSnapshot 隔离计算和绘制
- **Choreographer 驱动**：vsync 同步，精确帧控制

### 关键文件
1. **DanmakuView.kt**（550行）：public API，View 包装
2. **DanmakuPlayer.kt**（470行）：三线程调度器、Choreographer 管理
3. **DanmakuEngine.kt**（700+行）：核心弹幕逻辑（spawn、layout、render）
4. **CacheManager.kt**（500+行）：Bitmap 缓存、线程管理、内存池
5. **DanmakuTimer.kt**（100行）：System.nanoTime() 驱动、平滑时间
6. **DanmakuModels.kt**：配置类（DanmakuConfig、DanmakuSessionSettings）
7. **model/**
   - **DanmakuItem.kt**：包装 Danmaku + 缓存状态
   - **RenderSnapshot.kt**：双缓冲快照
   - **DanmakuInlineSegment.kt**：文字/emoji/高赞图标混合渲染

### 性能指标
- MAX_SPAWN_PER_FRAME: 48
- MAX_PENDING: 260
- MAX_CACHE_REQUESTS_PER_FRAME: 8
- BITMAP_POOL: 50MB / 72 个
- MAX_DELAY_MS: 1600ms
- MAX_CATCH_UP_LAG_MS: 1200ms

### 关键特性
1. **轨道管理**：滚动/顶部/底部分离，每轨道前后间距检查
2. **速度叠加**：baseSpeed × playbackSpeed × speedLevel 系数（图表约 1.5 倍）
3. **Pending 队列**：轨道满时入队延迟重试，超时丢弃
4. **异步缓存**：CacheThread 构建 Bitmap，volatile 发布到主线程
5. **Inline 段**：Unicode emoji + B站自定义表情 + 高赞图标
6. **蒙版**：onDraw 时 canvas.clipPath()，SVG Path 缓存
7. **流控**：缓存请求每帧限 8 个，队列深度限 48，防止堆积
8. **平滑时间**：System.nanoTime() 消除 position 抖动（seek/暂停恢复/变速时重新锚定）

### 渲染管线
```
CacheThread（HandlerThread）
  ↓ 构建 Bitmap （文字+emoji）→ item.cacheBitmap
  ↓ 发布 invalidate

ActionThread（HandlerThread）
  ↓ Choreographer → act()
  ↓ pruneExpired, retryPending, spawnNew, requestCacheBuilds
  ↓ 写 RenderSnapshot（双缓冲 A/B）→ latestSnapshot

Main Thread
  ↓ onDraw(canvas)
  ↓ DanmakuTimer.step() 平滑时间
  ↓ 读 snapshot，调用 release() 唤醒 ActionThread
  ↓ 逐项: cacheBitmap ? drawBitmap() : drawText fallback
```
